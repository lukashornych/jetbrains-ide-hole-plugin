Hole plugin for IntelliJ · design mockup · draft 4 · 21 Oct 2026

Hole Tool Window

A working sketch of the plugin described in documentation/specification.md. It is a bottom tool window, like the built-in Terminal, where each tab is one running sandbox. Draft 3 adds links to the Hole settings files in the dialog and settles the Hole changes the plugin needs, which are written up in documentation/hole-assignment-instance-id-and-list-json.md.

The tool window

Tab titles show the agent and the title the agent writes to its terminal. Click the tabs to switch. Closing a tab sends SIGINT, shows Stopping, then selects the previous tab. + opens the New Sandbox dialog. The arrow next to it lists favourites: click a name to start it, or the bug icon to start it in a debug shell.

Decisions

Status after the first review. Where a decision has a visible spot, the same number marks it in the mockups above.

  1. 1

    Tab title Agreed

    agent[:profile] · agent title. The agent title is whatever the agent sets through the terminal title escape (OSC 0/2), so the tab shows what the agent is doing.

    Until the agent sets a title, or for agents that never set one, the tab shows the project folder in italics. A debug run shows a bug icon.

  2. 2

    “+” and the favourites dropdown Agreed

    + opens New Sandbox. The arrow next to it lists favourites for a one-click start, with a debug start on each row, plus New Sandbox… and Edit Favourites….

  3. 3

    Header fields Agreed

    Instance ID, Docker, settings, project path and uptime. A debug run also shows a Debug Shell pill. The network is left out.

  4. 5

    Where favourites are stored Agreed

    Both. Each favourite says where it lives: this project (.idea/hole.xml) or all projects (IDE settings). The dropdown groups them that way.

  5. 4

    Getting sandbox metadata without parsing the terminal Agreed Hole change

    JSON cannot come out of hole start, because its terminal belongs to the agent. The plugin needs two things instead: a way to know which instance a tab started, and a machine-readable way to read that instance.

    The plugin picks the six-character ID and passes it in with hole start … --instance-id r8tq2c, and Hole rejects an ID that is already running. The plugin then polls hole list --json r8tq2c, which also reports a lifecycle status. The terminal stream stays untouched. For Hole versions without these options, the plugin falls back to matching Instance ID: ([a-z0-9]{6}) in the output and parsing the table.

    Assignment for Hole: documentation/hole-assignment-instance-id-and-list-json.md.

  6. 6

    Hole's own prompts Agreed

    Prompts such as Update agents now? [Y/n/s] stay in the terminal for the user to answer.

  7. 7

    How exit is sent Agreed

    SIGINT, no confirmation. After 30 seconds the header offers Force Stop.

  8. 8

    Debug mode Agreed

    A separate run action, Start in Debug Shell, beside Start. It uses the same form and leaves out the agent arguments. The command preview shows both commands.

  9. 9

    Project path Agreed

    An editable combo that defaults to . and accepts any absolute path. Its dropdown lists the git worktrees from git worktree list --porcelain.

    The plugin starts the process with the IDE project root as its working directory, so . means that root.

  10. 10

    Shell or direct process Agreed

    hole runs directly as the terminal's process.

  11. 11

    Ad-hoc starts and favourites Agreed

    New Sandbox opens with defaults. A favourite only exists when the user saves one.

  12. 12

    Remember the last ad-hoc values? Agreed

    No. New Sandbox always opens with defaults, and there is no Recent group.

  13. 13

    Hole settings files Agreed

    Both dialog views link to the global settings file and, if it exists under the selected project path, to the project's .hole/settings.json. Open opens the file in an IDE editor tab, and the arrow icon opens it in the system's default editor. The plugin does not build a GUI for the settings themselves, because their keys change often.

    The paths follow Hole's rules: HOLE_SETTINGS_FILE or ~/.hole/settings.json, and HOLE_PROJECT_SETTINGS_FILE or <path>/.hole/settings.json, read from the IDE's environment. The existence check runs again whenever the project path changes. For a running sandbox, settingsFiles from hole list --json names the exact files it was started with.
